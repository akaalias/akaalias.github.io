And there lies the trap! 😂
It's because there isn't any proper auto-compacting for sessions.

Thus, if you create a tool in a session it is logged both to your
~/.openclaw/agents/main/sessions/sessions.json

AND will be linked as context via your current session's ~/.openclaw/agents/main/sessions/[UUID].jsonl
file - both of which are sent as context to the LLM inference API as context of the current chat/request.

So a simple, 'Hey' can actually contain the full build of your tool, and modifications of it, edits, uses, chats and versions and revisions of it, logged uses of it, + the session file + 'Hey'
= shedload of tokens!

Workarounds for building tools and in general:
1) Always use a subagent - just ask it to:
"use another agent to [do X,] and when done add it to 'memory' "
and it will be in a session file outside the main one,
1b) (make sure you have the memories skill enabled!)

2) When working on it for a while, and when done - before finishing the session use:
/compact slash command
to keep the tokens controlled, so even if it is referenced in the future it has been pruned.

3) When finished, run /new to clear the session/tokens and start out with just the base context/memories/last pruned session as context.

After a while though even memories etc can build up, that's when using lots of individual agents comes into it, the main agent becomes the orchestrator and only sends the relevant request and relevant context needed for it per task to the sub-agent.
